# سلام DNA

`helix init` این فایل را در `dna/doc/hello_world.md` قرار داد، و موتور DNA آن
را در `doc/hello_world.md` نمونه‌سازی (instantiate) می‌کند. این دو نسخه کل
ایده را در مقیاس کوچک نشان می‌دهند: `dna/` DNA ادغام‌شده را نگه می‌دارد و
پروژه نمونه‌هایی را که از آن ساخته شده‌اند.

## 1. پیکربندی: `dna/_dna.json`

تنها جایی که پیکربندی DNA در آن قرار دارد. `role: "project"` می‌گوید که
`dna/` توسط helix تولید می‌شود، و `layers` بسته‌های DNA را که باید اعمال
شوند فهرست می‌کند — به ترتیب اعمال، آخرین لایه برنده است.

## 2. بسته‌های DNA دلخواه را اضافه کنید

بسته‌های DNA بسته‌های معمولی هستند. `helix add` یکی را به عنوان
dev-dependency نصب می‌کند و نامش را به `layers` اضافه می‌کند:

```bash
helix add dna_dart                                  # pub package
helix add @tssuite/dna-base                         # npm package
helix add https://github.com/ggsuite/dna_base.git   # git repository
```

اعلام دستیِ وابستگی هم کار می‌کند — در آن صورت خودتان آن را زیر `layers`
فهرست کنید، چون وابستگی‌ای که فهرست نشده باشد لایه نیست.

## 3. آزمون‌ها را اجرا کنید — موتور همین است

`helix init` فایل `test/dna/dna_test.dart` (Dart) یا `test/dna/dna.spec.ts`
(TypeScript) را قرار داد. هر اجرای آزمون DNA را نمونه‌سازی می‌کند و بررسی
می‌کند که نمونه‌ها هنوز با آن مطابقت دارند:

```bash
dart test        # or: pnpm test
helix build      # the same run, without a test framework
```

اولین اجرا `dna/`، نمونه‌ها و `dna/_generated.json` را می‌نویسد و دقیقاً همین
فایل‌ها را با پیام `#gg: generated DNA` commit می‌کند.

## 4. چه چیزی کجا قرار می‌گیرد

| در DNA                         | نمونه‌سازی در             |
| ------------------------------ | ----------------------- |
| `dna/LICENSE`                  | `LICENSE`               |
| `dna/doc/hello_world.md`       | `doc/hello_world.md`    |
| `dna/dot-vscode/settings.json` | `.vscode/settings.json` |
| `dna/_vars.json`               | — خصوصی، داخل می‌ماند   |

نقطه‌ی ابتدایی به صورت `dot-` نوشته می‌شود، چون انتشار در pub هر مسیری را که
با نقطه شروع شود حذف می‌کند. هر بخش از مسیر که با `_` شروع شود خصوصی است و
هرگز نمونه‌سازی نمی‌شود.

## 5. فایل‌های تولیدشده را ویرایش نکنید

نمونه‌ای که به‌طور محلی تغییر دهید به پوشه‌ای زیر پوشه‌ی موقت سیستم کپی و سپس
با محتوای DNA بازنویسی می‌شود؛ گزارش مسیر آن نسخه‌ی پشتیبان را چاپ می‌کند. به
جای آن، آنچه را یک لایه ارائه می‌کند تغییر دهید:

- فایلی با همان مسیر در لایه‌ای بعدی فایل را جایگزین می‌کند،
- `X.overrides.json` فیلد به فیلد در `X.json` ادغام می‌شود،
- `X.overrides.md` بخش‌هایی را که یک فایل markdown علامت‌گذاری کرده جایگزین
  می‌کند.

هر فایل موجودی که یک اجرا بازنویسی یا حذف می‌کند باید از قبل commit شده باشد
تا هر بازنویسی از طریق git قابل بازیابی بماند.

## گام‌های بعدی

- لایه‌های خود را به `dna/_dna.json` اضافه کنید.
- README مربوط به helix مرجع کامل است: متغیرها، بازنویسی‌ها (overrides)،
  بلوک مدیریت‌شده‌ی `CLAUDE.md` و قواعد تفکیک (resolution).
